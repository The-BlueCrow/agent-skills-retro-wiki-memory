# 适用边界与故障排查

## 适用边界

| 场景 | 是否支持 | 说明 |
|------|---------|------|
| 文本为主的技术/工作对话 | ✅ 最佳场景 | 6 路分析的设计目标 |
| 含少量截图/报错图的对话 | ✅ 支持 | 主 agent 提炼素材时描述图片内容即可 |
| 纯图片 / 无文字说明 | ⚠️ 受限 | 无文字上下文，提炼质量低；建议先转成文字描述再复盘 |
| 单人单会话 | ✅ 设计场景 | 基于当前一次对话的上下文 |
| 多人协作 / 跨会话 | ❌ 不支持 | 本 skill 只看当前对话上下文，无法合并多个会话或多个人的输入 |
| 超短对话（<4 轮） | ❌ 不建议 | 多半无可提取经验，触发后 skill 会主动问你是否真要复盘 |
| 实时流式 / 边对话边记 | ❌ 不支持 | 本 skill 是对话结束后的回顾式沉淀，非实时记录器 |

## 常见问题（FAQ）

### Q1：并行调用 Agent 失败 / 平台不支持单消息多工具并行？

**诊断**：报错类似"无法同时调用""工具不支持并发"，或只有第一个 agent 返回。
**解法**：降级为主 agent 串行执行阶段一的 6 步，按表格顺序逐项产出，质量不变只是更慢。
> 不要因为无法并行就放弃整个复盘。

### Q1.5：subagent 调用超时/限流/返回错误怎么办？

**诊断**：某个 subagent 长时间无响应、报 rate limit、或返回报错而非正常产出。
**解法**（按顺序自动尝试，不需要用户介入）：
1. 该维度重试 1 次。
2. 仍失败 → 主 agent 自己用 prompts.md 里对应模板补跑该维度（不再起 subagent）。
3. 多个维度连续失败 → 整体降级为快档（主 agent 跑 ①理解问题 ②抽取解法 ④防复发）。
4. 重试都失败且用户在线 → 告知「N 路成功/M 路失败」，询问是否用已有产出继续。
> 关键：已成功的维度产出要保留，不因单点失败丢掉。最坏情况下主 agent 自己接手所有维度。

### Q2：记忆文件写入报错（路径不存在 / 权限拒绝）？

**诊断**：
- 路径不存在 → 记忆文件尚未创建，或框架路径表里查不到。
- 权限拒绝 → 文件被占用或目录无写权限。
**解法**：
1. 用 `node -e "console.log(require('os').homedir())"` 确认真实 HOME（Windows 下 Git Bash 的 `~` 可能错指他处）。
2. 文件不存在则先 `mkdir -p` 建目录再创建文件。
3. 框架路径不确定时**询问用户**，或用通用兜底 `项目级 AGENTS.md`。

### Q3：某个 subagent 产出质量差 / 跑题 / 字数超标？

**解法**：主 agent 对该路单独重跑，强化 prompt（明确字段清单 + 字数上限 + "直接输出不要寒暄"）。
不需要 6 路全部重跑。

### Q4：对话太短，不知道该不该复盘？

用「值得沉淀」启发式判断（踩坑/决策/可复用产出/工具非常规用法，满足任一）。
全不满足 → 直接问用户"这次要沉淀吗"，别硬凑。

### Q5：写入全局记忆文件会污染后续所有会话吗？

不会失控：阶段三有**写入前确认门控**——内容先给用户看过再落盘。只写精简的可迁移规则
（4 行模板），不写整篇经验。若不放心，落到项目级 `AGENTS.md` 而非全局文件。

### Q6：6 个维度必须全跑吗？

不必。按对话复杂度选档：
- **快档**（对话 <8 轮、1-2 个坑）：主 agent 自己跑 3 个核心维度（①理解问题 ②抽取解法 ④防复发），跳过互链/排版/记忆文件，只落盘一篇简短文档。
- **全档**（对话长、≥3 个坑或架构决策）：6 路并行（或串行降级）。
- 判定：≤2 个坑用快档，≥3 个坑或涉及架构决策用全档。用户明说「简单记一下」强制快档，「完整复盘」强制全档。
