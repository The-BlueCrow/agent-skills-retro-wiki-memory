# 半导体CIS资源映射拓扑图工具 + nginx局域网部署（含Windows踩坑修复）

## TL;DR

- **做了啥**：映射表(针卡NET/32Site/DPS) → 可视化拓扑图HTML工具，升级为 nginx+waitress+Flask 局域网共享架构
- **价值**：手动查表 → 自动可视化，团队浏览器直接访问 `http://本机IP/`，拓扑可保存/画廊查看
- **最值钱**：⭐ 6个Windows环境坑的速查表 + 多Agent协作+QA对抗审查的工程化模板

---

## 一、背景与目标

OVB0DH0 CIS芯片CP测试项目存在3类资源映射表（针卡NET表、32Site对应表、DPS表），描述信号从DUT到机台物理通道的多层映射。目标：做成可视化拓扑工具，并升级为局域网多人共享。约束：Win10+Git Bash（PATH空）、nginx1.30已装、需离线单文件HTML无外部依赖。成功标准：所有节点正确渲染无崩溃、局域网可访问、数据可持久化。

---

## 二、整体架构

```
局域网同事浏览器 (无需装任何东西)
        │ http://本机IP/
        ▼
┌─────────────── nginx (80端口) ──────────────┐
│  ① 静态托管: 拓扑图HTML                       │
│  ② 反向代理: /api/* → waitress:5000          │
└──────────────────────┬───────────────────────┘
                       ▼
┌─────────── waitress (Windows原生WSGI) ───────┐
│  管理 Flask worker进程, 处理并发              │
└──────────────────────┬───────────────────────┘
                       ▼
┌─────────── Flask + SQLite ──────────────────┐
│  /api/layouts POST保存 / GET列表 / GET详情 / DEL│
└──────────────────────────────────────────────┘
```

**架构要点**：nginx 托管静态前端 + 反代动态API；waitress 是 Windows 上 Gunicorn 的替代（Gunicorn依赖POSIX fork不支持Windows）；SQLite 单文件持久化。

## 四、⭐ Windows环境踩坑速查（坑-因-解对照表）

| 坑 | 现象 | 根因 | 解法 |
|----|------|------|------|
| **PATH为空** | ls/grep/node/python全command not found | bash启动PATH未注入，harness二次清空 | 命令体首行 `export PATH="/usr/bin:/c/Program Files/nodejs:/c/Python314:$PATH"` |
| **null崩溃** | `Cannot read properties of null (reading 'nodes')` | `setAllExpanded`读`this.graph`在`init()`赋值`this.graph`之前两行 | 调用顺序：init先行；加 `var g=this.graph\|\|App.graph; if(!g)return` 兜底 |
| **Gunicorn不工作** | Windows启动报fork错误 | Gunicorn依赖POSIX fork，Windows没有 | 改用 `waitress`：`waitress.serve(app,listen='127.0.0.1:5000')` |
| **nginx reload失效** | 改配置reload后仍返回旧页面 | Windows僵尸worker无法干净关闭 | 必须 `nginx -s stop` 后重新 `nginx`（不能只reload） |
| **TSD加密乱码** | shell `>`重定向写入的文件变乱码 | TSD驱动加密文件系统 | 改用 Edit/Write 工具写文件，禁用shell重定向 |
| **正则误判** | `S2_CH13`(无子标识合法格式)被判UNKNOWN | 正则`_(\S+)`强制要求第三段 | 改可选 `(?:_(\S+))?`，解析时 `m[3]\|\|''` 兜底 |

### 通用预防 checklist

- [ ] 命令首行已 export PATH 并 `which ls` 验证
- [ ] 所有 `this.X` 读取点在赋值之后（写先于读）
- [ ] 正则有合法缺省边界 case（空子标识/无后缀）
- [ ] WSGI服务器已确认跨平台（Windows禁用Gunicorn）
- [ ] nginx reload 后校验配置真生效，失败改 stop+start
- [ ] 文件写入用 Edit/Write（非 shell `>`）
- [ ] HTTP 请求体中文走文件 `-d @file`（非单引号内联）

### 早发现信号

| 现象 | 立即警觉 |
|------|----------|
| `command not found` | PATH未注入 |
| `Cannot read properties of null` | 时序/null缺防御 |
| 整类节点不显示 | 过滤逻辑漏数据源（如只看一跳）|
| 正则该过的过不掉 | 边界格式漏覆盖 |
| 改完无变化 | reload未生效 |
| 文件打开是乱码 | 命中TSD加密 |

## 五、可复用资产

### nginx 配置（80端口托管+反代）

```nginx
server {
    listen 80;
    server_name localhost;
    root "C:/path/to/前端目录";
    index 你的页面.html;
    location / { try_files $uri /你的页面.html; }
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
    }
}
```

### waitress 启动（Windows替代Gunicorn）

```python
import waitress
from app import app, db
db.init_db()
waitress.serve(app, listen='127.0.0.1:5000', threads=8)
```

### 正则边界修复模板

```javascript
// 修复前（强制子标识，误判无后缀合法格式）
RE_IO: /^S(\d+)_CH(\d+)_(\S+)$/
// 修复后（子标识可选）
RE_IO: /^S(\d+)_CH(\d+)(?:_(\S+))?$/
// 解析时兜底空值
subId: m[3] || ''
```

### node 实跑定位前端崩溃（开发期）

```bash
# 用node加载HTML内联JS + 最小DOM桩，真实执行App.loadSample()，打印err.stack
export PATH="/c/Program Files/nodejs:$PATH"
node -e 'const vm=require("vm");/* 提取<script>内容，桩掉document，调loadSample */'
```
