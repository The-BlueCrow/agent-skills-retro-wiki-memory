# session-retro —— 单次会话体检

AI 协作结束（或告一段落）时，把整段对话过一遍：哪些动作值、哪些动作废、下次怎么少绕弯。产出控制在一页内。

## 何时触发

- 任务完成、验收通过后；
- 会话被叫停或方向被推翻时（这种时刻信息量最大）；
- 长会话的里程碑处（每完成一个子任务可以只跑核心三问：目标 / 路径 / 收获）。

## 核心原则

1. **数据源就是当前对话**：全部原料都在上下文里，不需要外抓。凭印象写的复盘是编的，宁可不写。
2. **只写结论，不复述过程**：读者（包括未来的自己）没耐心看流水账，每条都要带"下次怎么办"。
3. **诚实优先**：该指出用户指令含糊就说，委婉但不回避；该承认自己绕弯就承认，不粉饰。
4. **克制**：一页以内。超了就说明想写小作文，压回去。

## 六个维度与判定口径

每个维度给绿 / 黄 / 红三档，够到阈值就如实标，不为好看降档：

### 1. 目标达成
- 绿：交付物与验收标准逐条对上，验证过（跑通 / 读过成品），无遗留。
- 黄：主体完成，遗留小尾巴且已明确告知。
- 红：交付了但没验证；或范围悄悄缩水没说。
- 关键问题：验收标准是谁定的？中途变过吗？变过的话双方对齐了没有？

### 2. 路径效率
- 绿：关键步骤基本无废动作；同类读取 / 检索没有重复第二遍。
- 黄：有可省的往返（例如顺序反了要补读、试了明显的死路）。
- 红：同一文件读三遍以上 / 同一命令重试到三次以上 / 返工重做整个交付物。
- 关键问题：哪些调用砍掉也照样出结果？当时为什么觉得它必要？

### 3. 交互质量
- 绿：该澄清的问了、不该问的直接做了；用户全程纠正不超过一次。
- 黄：用户纠正 2–3 次，或该问的没问导致返工。
- 红：同一类纠正出现两次以上（说明没在听）；或替用户做了本该问的决定。
- 关键问题：每次纠正是"信息我本来就没有"还是"我理解偏了"？前者补信息渠道，后者补确认动作。

### 4. 资源消耗
- 绿：读的东西都用上了，没有空转。
- 黄：有白读的文件、白跑的搜索（结果没进任何决策）。
- 红：明显烧钱的大动作（批量抓取、长循环）发生在方向未定之前。
- 口径：不精确计数，问一句"有没有哪次调用删掉也不影响结果"。

### 5. 风险与边界
- 绿：改动前报批、凭据不落盘不外传、出错如实上报。
- 黄：先斩后奏但事后补报且可回滚。
- 红：未报批的外部动作 / 凭据裸奔 / 失败时编造结果——**任何一条触红，本次复盘把它放第一条**。
- 关键问题：这次动过哪些外部状态（推送、发布、删改线上东西）？逐个对得上吗？

### 6. 可迁移收获
判据只有一条：**这个坑未来还会遇到吗？**
- 会，且偶发 → 写成教训条目（格式：一句话根因 + 证据 + 下次怎么办）。
- 会，且反复出现（同类 ≥3 次） → 升级为流程规则，写进你自己的操作规范。
- 不会 → 不入库，留在本次复盘里就够。
- 候选收获为零是正常的，不要为凑数硬编。

## 输出模板

```
# 会话体检 <YYYY-MM-DD> <一句话主题>

✅ 达成：<交付了什么，怎么验证的>
📐 路径：<黄 / 红维度点名，一句话>
⚠️ 偏差：<交互 / 资源 / 风险里的实际问题；没有就写"无">
💡 收获：<0–3 条候选收获，格式照第 6 维度；没有就写"无">
📌 遗留：<未完事项 + 下一步；没有就写"无">
```

## 注意事项

- 复盘不是审判：目标是让下一次更省，不是给这次打分。不输出"总分 / 评级"，单维度颜色已经够用。
- 用户的口头反馈是最高权重输入：用户说"生硬""绕了"，直接记为该维度的黄 / 红，不需要自我辩护。
- 同一段对话只在方向变化后重跑复盘，不刷同一页。
- 复盘产出里的凭据、私有地址照常脱敏，和写任何文档一样。
