# lessons-learned.md 合并 SOP（教训库整理）

## 何时触发合并

- **月度整理日**：每月一次，合并同类、删纯重复（lessons-learned.md 头部「入库查重」规矩，2026-10-07）。
- **超线强制**：条目超 60 条强制整理（同上）。
- **追加时挂靠发现**：Append SOP 第 1b 步——写新条前 grep 到同主题旧条，能并就并进旧条，不新开号。

## 何时合 / 何时不合

**合**：同根因（同一机制层原因的两次表现）；一条是另一条的子集；同一主题的复发记录（并进主条当第 N 次复发）。

**不合**：
- 仅表面相似、根因不同（并了会把两个独立教训的检索路径掐断一条）；
- 被并条有主条没有的检索锚点——必须先把锚点词并进主条再删（锚点是未来检索的入口，丢了等于这条教训失联）；
- 跨主题「顺手整理」——一次合并只动一个主题域，跨域批改是并发事故的温床。

## 合并五步

1. **查重定位**：`grep -n "关键词" <MEMORY_DIR>/lessons-learned.md` + 读文件头部「旧编号并入指针」行，确认候选对。
2. **定主条**：保留检索锚点更全、解法更完整的那条。指针方向固定 **旧→新**（被并的旧号指向保留号，历史格式：`24→12`）。
3. **处置被并条**：整条删除；头部「旧编号并入指针」行追加 `旧→新`（照抄现格式，别自创记法）。
4. **主条刷新**：刷日期、吸收被并条的解法与检索锚点、文内注明「（含原 #N）」。
5. **验收 + 固化**：跑下方三项断言 → `tail -3` 复检 → 一笔 commit（message「复盘：lessons 合并 <N>→<M>」；`git add` 前 `git diff` 确认没把别人未提交的条目扫进来，README Append SOP 同款规矩）。

## 三项验收断言（带口径命令）

```bash
# ① 编号唯一：无重复号（输出非空 = 失败）
grep -oE '^[0-9]+\. \*\*' <MEMORY_DIR>/lessons-learned.md | grep -oE '[0-9]+' | sort -n | uniq -d

# ② 退役号指针齐：每个被并编号都能在头部指针行找到「旧→新」（把 N 换成本次并掉的号逐个查）
grep -n '旧编号并入指针' <MEMORY_DIR>/lessons-learned.md | grep -c '<旧号>→'

# ③ 计数对账：最大曾用编号 − 退役号数 = 实际条目数（README「新条从 #NN 起」同步更新）
grep -oE '^[0-9]+\. \*\*' <MEMORY_DIR>/lessons-learned.md | grep -oE '[0-9]+' | sort -n | uniq | wc -l
```

任一断言不过 = 合并未完成，回第 3 步查处置；不许宣布完成（复盘硬门槛同款）。

## 副本与并发

- **副本不是事实源**：`lessons-learned.md.bak-*` 系列（如 `bak-merge-20261007`）只是改动前快照，合并一律以正本为准，别拿副本对账。
- **动共享文件前重读尾部**：lessons-learned.md 是多 agent 共用文件，改前 `tail -30` 重读——10-12 曾发生并发插条被覆盖的实踩（retrospective-ops 八校对第 7 项来源）。

## 与 Append SOP 的分工

| | Append SOP（deep-memory/README.md） | 本 SOP |
|---|---|---|
| 管什么 | **单条追加**：挂靠优先、编号规则、格式、收尾复检 | **批量整理**：月度/超线时的合并动作 |
| 共用铁律 | 编号只增不复用（含退役号）；新条 = 历史最大曾用编号 + 1 | 同左 |
