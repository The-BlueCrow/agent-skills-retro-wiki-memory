# 复盘准则（通用版）

- 适用：用户说「复盘」时；以及用户纠错后、跨 agent 交接失败后、连续两次踩同类坑后、一次改动牵动 ≥3 个文件或外部服务后的自查。
- 结论先行：**四处都落文件 + 八项校对全过 + wiki lint 0 issues + 一笔 commit，才算复盘完成。** 任何一项不过，只能报「复盘未完成 + 卡在哪」，不得宣布完成。

## 一、四连（缺一不算）

### ① 深层经验 `<MEMORY_DIR>/lessons-learned.md`
- **先挂靠后开号**：`grep -n "关键词"` 查同主题旧条，能并就并进旧条并注明「原 #N」；查无同题才新开号，新号 = 历史最大曾用编号 + 1；不跳号、不重用退役号；追加前用 `grep -oE '^[0-9]{1,4}\. \*\*' … | sort | uniq -d` 验编号无重复。
- **四要素齐全**：现象（谁在哪天问了什么/踩了什么）→ 根因（写到机制层，不是「我忘了」）→ 解法（可执行动词句，带命令）→ 自检句（下次问自己哪一句）。缺自检句 = 只是日志。
- 一事一条；禁止把当次流水账贴进去（日期叙事、进程号堆砌是已知反模式）。
- **落点判据**：执行动作是「下次遇到 X 类任务怎么做」→ 写技能不写 lessons；「这环境有什么坑/事实」→ 写 lessons；「这台机器/服务现在什么样」→ 写 wiki 或服务器笔记。

### ② 技能 `<SKILLS_DIR>/<name>/SKILL.md`
- 落点 = **下次同类任务实际会 load 的那个技能**；判错落点规则就白写。
- 写法：祈使句 + 为什么，一条一个教训；坑带**实踩日期**与回滚方式（回滚 tag / `.bak` 文件名）。
- **写前先 grep 该技能**，已有同义规则就不重复（重复 = token 膨胀 + 规则冲突）。

### ③ Wiki `<WIKI_DIR>/`
- 建页门槛：2+ 来源，或单来源核心对象（此时 `confidence` 必填）；`sources` 必须真实一手，**禁止同域互链凑数**。
- frontmatter 六字段齐（title/created/updated/type/tags/sources），`tags` 取自 SCHEMA 白名单。
- 出链 ≥2，**且至少 1 个别页链入**——否则 lint 判孤儿页（medium 也算 FAIL）。
- **wiki 内部三连同步缺一不可**（与复盘四连是两回事）：`index.md`（分区计数 + Total pages + Last updated 三处）→ 对应域 `GUIDE.md` 收录清单加行（**行数必须 = 实际页文件数**）→ `log.md` 加一条（建/改了什么、lint 结果）。
- 改已有页要 bump `updated`，并考虑是否牵动 index Total。

### ④ 提交 `git commit`
- 知识层文件（wiki + 记忆库 + 技能库）纳入一个**本地** git 仓；**永不推远端**。
- 三处都是**原地覆盖写**（整文件重写、patch、追加），改坏只有 commit 能回滚——所以第四环不是可选项。
- 收尾前 `git status` 看清改动，**只 `git add` 自己动过的文件**；禁 `git add -A` 收别的 agent 的活（这三处常多 agent 共用）。
- 提交前重跑凭据扫描，**只列文件路径、绝不打印内容**：`grep -rlI --exclude-dir=.git -e 'ghp_' -e 'github_pat_' -e 'BEGIN RSA' <知识层各目录>`；命中先判读性质（文档示例 vs 真凭据），真凭据 → 先脱敏或改 `.gitignore` 排除。
- 一笔 commit 装一次复盘的全部改动（lessons + 技能 + wiki 一起），message 写「复盘：<主题>」。
- 回滚口径 = `git checkout -- <path>`；动手前先 `git log --oneline -1` 确认基线在。

## 二、八项校对（复盘的复盘，逐项留一行实测输出）

1. **lint**：`python3 <技能目录>/scripts/wiki-lint.py <WIKI>` → **0 issues**（medium 也算不过；孤儿页就是 medium 被抓的）。
2. **计数必带口径命令，且与权威口径源一致**：口径源 = 生成/校验该数字的权威脚本里的命令。**禁止手数 `ls -1 | wc -l`**——顶层条目数与脚本口径经常不一致，以脚本口径为准。
3. **文中事实断言逐条落地复核**：md5、路径、端口、进程号、**API 端点名**都要现场 `grep`/`run` 再写——凭印象把具体路由写成泛称是最常见翻车点。
4. **占位符清零**：`<见…>`、`<填>`、`TODO`、`待补` 一律不允许留在复盘产物里。
5. **编号唯一**：lessons 编号、待办编号、log 条目不撞号、不跳号。
6. **改完回跑依赖方**：改共享看板 → 实跑其配套校验脚本（纯确定性、0 token）确认提取非空且行数没断；改技能 → 注明「开新会话才生效」；改服务 → 照对应验收清单。
7. **并发写检查**：动共享文件（看板 / wiki / lessons）前重读尾部，确认期间没被别人写入——并发插条实踩过：晚一步就可能覆盖别人的条目；提交前同理，`git status` 分清哪些是自己的改动。
8. **结构完整性**：共享看板段数/流水条数对账；wiki：lint 报的页数 = `index.md` Total = 实际 `.md` 文件数；GUIDE 收录清单行数 = 该域页文件数。

## 三、硬门槛（任一不过 → 报「复盘未完成」）
- [ ] 四连里 ①②③ 三处都有**文件级改动**（口头/聊天里说明不算）
- [ ] 第④环有**一笔 commit**，`git status --porcelain` 收尾干净
- [ ] wiki lint **0 issues**
- [ ] 八项校对每项有一行实测输出（命令 + 结果）
- [ ] 每个数字都带口径命令，每条事实断言都带出处或现场复核记录
- [ ] 校对抓到的错误**当场修复并复检**；修不了的列进待办，不许静默跳过
- [ ] 向用户交付：四连落点清单（含 commit hash）+ lint 结果 + 本轮抓到的错误与处置

## 四、反模式（出现即打回重做）
1. 复盘 = 复述今天干了什么（流水账）。
2. 只写「做了什么」，不写「为什么错 / 下次怎么防」。
3. 规则与既有规则重复，或把同一教训在 lessons、技能、wiki 三处各抄一遍（各写**该层该有的形态**：教训/规则/事实，不互相复制段落）。
4. 数字不带口径、断言不带出处（拿上文或记忆当证据）。
5. 用别人的「已确认送达/已核对」代替自己复核（发件方的自检不是收件方的证据）。
6. lint 没跑 / 没过就宣布完成。
7. 为过 lint 而凑链接、凑来源、凑入链——入链要真的让邻居页受益。
8. 三处都改完就宣布完成、**漏掉第④环 commit**（改动无版本可回滚，等于白改）；或 `git add -A` 把别的 agent 的半成品一起收进自己的 commit。

## 五、收尾自检五问（收尾前逐条答「是」）
1. ①②③ 三处都动了文件、第④环有 commit 吗？
2. wiki lint 0 issues 吗？
3. 每个数字我都能当场念出它的口径命令吗？
4. 文里每条事实断言是我现场验证的，还是从记忆/上文抄的？
5. 校对抓到的错修完复检了吗，没修的列待办了吗？
